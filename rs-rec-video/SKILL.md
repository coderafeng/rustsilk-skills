# 产品使用教程视频制作

> **定位**：把「业务流程 → 带配音的演示视频」这类任务做成可复现、可验收、可交接的工程。
> **通用性**：本文与具体项目、机器、录制器实现无关。项目落地信息（工具链位置、入口 shell、TTS 引擎、凭据通道、已交付链路）**另文件维护**，禁止写进本文（见末尾「项目落地文件」）。
> **阈值来源**：文中数字均为真实交付片子的实测值；换配音引擎、换语种、换业务后必须重新标定，不得沿用。

## 适用范围

**适用**：产品功能教程、新手指引、业务流程演示、缺陷复现录像、验收留证录像。
**不适用**：视频剪辑与二次创作、生成式视频、静态截图说明、无真实页面操作的纯动效片。

## 七条核心原则

| # | 原则 | 违反后的真实表现 |
|---|---|---|
| 1 | 旁白只说画面里真实存在的东西 | 配音说"共 15 条"、画面只有 10 条，观众第一眼失去信任 |
| 2 | 事实来自机器探测，不来自印象 | 字段名、按钮文案、下拉选项、条数全靠手写，页面一改文案集体说谎 |
| 3 | 时长问题在开录前解决，不在录后 | 录完才发现成片超时、某段静默 30 秒，只能整轮重录 |
| 4 | 补静默靠加信息密度，不靠放慢语速 | 拉长停顿掩盖空白，观众感知是"拖"而不是"清楚" |
| 5 | 演示数据必须可还原，还原要二次确认 | 库里留着上轮演示行，下一轮只能拍到"重复创建被拦下"的异常分支 |
| 6 | 图文不符即中断，不产出次品 | 断言失败还继续录，交付一支必须人肉逐帧检查的片子 |
| 7 | 业务流程先书面确认，再动手制作 | 环节漏了/顺序错到录制阶段才发现，旁白、断言、镜头、清理策略全部返工 |

## 第 0 步：开工闸门（以下各项全部通过才准开浏览器）

### 0.1 与需求方确认的参数（不得默认）

| 参数 | 要点 | 取值建议 |
|---|---|---|
| 覆盖范围 | 是否含回退/撤销/异常分支 | 回退链路通常使时长 +30%，必须提前定 |
| 出镜身份 | 几个角色、是否实拍切换登录 | 每次换人登录实拍约 25s，计入总时长 |
| 目标时长 | 成片秒数上限 | 反推字数：**字数 ≈ 目标秒数 × 每秒字数 × 0.95** |
| 分辨率/帧率 | 交付清晰度 | 1080p/30 为主；画面以文字表格为主时 720p 足够 |
| 配音方式 | 云端或本地引擎 | 涉及真实业务数据、账号名时**必须本地引擎**，文本不出本机 |
| 视觉增强 | 光标、点击涟漪、字幕胶囊 | 教程类默认：滑行光标 + 点击涟漪 + 短语字幕 |

### 0.2 时长标定（每个环境做一次）

先合成 3~4 段样本旁白，实测**每秒字数**与**语音覆盖率**，再据此规划段数与字数。
未标定就开写旁白 = 后面每段时长都是猜的。

### 0.3 业务流程文档（确认闸门，成本最低的返工拦截点）

读完源码/需求后**第一件事不是写脚本**，而是把理解写成一份 `business-flow.md`：环节顺序与页面入口、操作角色、关键分支与回退路径、每步的数据与状态变化、演示起点数据形态、本片明确不覆盖的部分。

- 确认通过前：禁止写旁白、禁止写镜头脚本、禁止开浏览器。
- 与探测 JSON 分工：文档描述业务**应该**怎么走（人的共识），探测 JSON 描述页面**当前实际**是什么（机器观测）。冲突时以页面观测为事实，但必须**先改文档、重新确认，再改脚本与文案**，禁止只改脚本绕过文档。
- 该文档属**运行时输入**，收尾时不得当临时物删除。

### 0.4 工作区隔离

```text
<项目根>/.rs-rec-video/
├── _shared/                # 录制器上游资产、TTS 适配、通用 UI 原语（任务期只读）
└── <任务名>/
    ├── business-flow.md    # 业务流程文档（运行时输入）
    ├── segment-plan.md     # 片段划分与插卡计划（运行时输入，见 §0.5）
    ├── flow.mjs  narration.mjs  probe.mjs   # 任务脚本（运行时输入）
    ├── work/               # 探测 JSON、日志、抽帧、缓存、中间码流（可整体重建）
    └── out/<任务名>.mp4    # 成片
```

一任务一目录，不同任务禁止互读可变文件或向对方目录写入。验收判据：`work/` 可整体删除且不影响其他任务。
目录名以 `.` 开头是工具目录约定：多数 IDE 与文件管理器默认隐藏它，`git status` 里也不会被误当成业务改动；中间码流与成片体积大（数百 MB），是否入库由项目自行裁决，禁止把 `out/` 当成 `work/` 一起删。

### 0.5 片段划分与引导卡计划（确认闸门）

业务流程文档确认后、写旁白之前，把录制段与引导卡的划分写成一份 `segment-plan.md`，交需求方**书面确认**；未确认不得生成卡片、不得写录制脚本。

| 列 | 填什么 |
|---|---|
| 段 id | 与 flow / narration 脚本一致的段标识 |
| 覆盖动作 | 本段实拍完成的页面与操作 |
| 所属大阶段 | A / B / C…，与开头总览卡上列出的步骤一一对应 |
| 是否插卡 | **只有大阶段首段填「是」**，其余一律「否」 |
| 预计秒数 | 由 §0.2 标定的每秒字数反推 |

- **卡片密度上限**：中间引导卡数量 ≤ 开头总览列出的大阶段数 − 1；卡片累计时长 ≤ 成片总时长的 8%。
- **禁止按导航逐段插卡**：每个菜单跳转、每个子步骤（B1、B2…）都插一张卡，观众每隔十几秒就撞上一次静止画面，实测观感显著劣于少卡；插卡密度是体验问题，不是覆盖率问题，宁少勿多。
- 大阶段内部靠**旁白过渡句**衔接（"档案建好了，接下来排班"），不靠卡片。
- 划分粒度以**观众视角的步骤数**为准（开头总览上有几条，中间最多就几张卡），不是以流程图上的操作数为准。
- 事后重制（只改插卡密度、不改画面与语音）：从**无卡片流**重拼即可，不必重录；因此阶段 5 必须把无卡 clip 与卡片分别落盘，禁止只留拼接后的成品。
- 该计划表属运行时输入，收尾时不得当临时物删除；与探测 JSON 冲突时同 §0.3，先改计划表、重新确认，再改脚本与文案。

## 八阶段主流程

固定顺序，每阶段能单独执行，**失败即停、不进入下一阶段**。复制此清单跟踪进度：

```
- [ ] 0 冒烟先行        - [ ] 4 事实探测
- [ ] 1 环境自检        - [ ] 5 录制（主摄 + 切片）
- [ ] 2 起点核对        - [ ] 6 录后还原（恒定放 finally）
- [ ] 3 旁白测长        - [ ] 7 成片验收
```

| 阶段 | 做什么 | 通过判据 |
|---|---|---|
| 0 冒烟 | 3 段旁白 + 1 个页面打通全链路（启动→录制→转码→混流→时间轴落盘→中文渲染） | 冒烟片能播、字幕不乱码、音画同步 |
| 1 环境自检 | 校验外部工具可解析、配音指向预期引擎、目录可写；缺项**直接中止并打印缺什么** | 全绿才继续，禁止"先跑起来看看" |
| 2 起点核对 | 明确定义"干净起点"，有残留先复位，复位失败**不开浏览器**；破坏性复位要显式旗标 | 库处于可复现起点 |
| 3 旁白测长 | **开浏览器之前**把全部旁白合成一遍，打印每段 id/秒数/字幕/合计 | 逐段 `|语音 − 画面实拍| ≤ 0.5s`；超标段改文案，禁止改语速或加停顿 |
| 4 事实探测 | 产出探测 JSON，作为旁白与断言的**唯一事实源** | 关键字段无缺失（否则拒绝开录）；详见 [pitfalls.md](pitfalls.md) |
| 5 录制 | 见下节「录制策略」；无卡 clip 与引导卡**分别落盘**（保证事后可只改插卡密度重拼） | 退出码 0 且成片确实新产出，禁止用旧片冒充新片 |
| 6 录后还原 | 无论成败都还原；策略见 [data-reproducibility.md](data-reproducibility.md) | 库状态 = 阶段 2 定义的干净起点，且已二次确认 |
| 7 成片验收 | 门槛与命令见 [verification.md](verification.md) | 全部硬门槛达标，任一不达标必须重录 |

**多轮迭代是常态**：首跑到全通往往要迭代多轮。每轮在中断点写最小复现探针取证（转储真实 DOM / 捕获接口响应），据证修改，不凭猜测改代码。

## 录制策略：一条主摄 + 按时间轴切片（默认）

录制器实时驱动整条浏览器流程，成片时长 ≈ 实拍墙钟时间，**改任何动过画面或字幕的输入都要重录整条链路**。因此重录次数是这项任务的主要成本。

- **默认做法**：跑**一条带旁白的全链主摄**，再用主摄落盘的 timeline 按段精确切片，只对不合格段做单段隔离重录。相比"每段一次隔离录制"，把 N 轮实时重录压成 1 轮。
- **前提**：每段在流程脚本里包成可开关的段（如 `if (on('A1')) { say(...); await hold() }`），配合 `SEG_ONLY` 环境变量即可只跑所选段。
- **切片换算**：画面时间轴与语音共用同一换算，**必须含音频偏移量**：

  ```
  成片画面时间(s) = (段起始ms + audioOffsetMs − headTrimMs) / 1000
  audioOffsetMs ≈ padMs / 2      # 录制器为对齐音视频在头部补的静默
  ```

  漏掉 offset 会切到上一段画面并吃掉本段开头语音，且**光看时长看不出来**——所以切片后必须逐段验音轨（见 verification.md）。
- **取 timeline 文件**：录制工具常把本轮 timeline 随成片改名放到输出目录（如 `out/<成片名>.timeline.json`）。要优先取**成片同名旁文件**，不要扫目录拿"最新的"，否则会误用上一轮捕获跑的 timeline，段长与音画位置全错。
- **TTS 缓存对邻居敏感**：缓存 key 通常含前后段文本，改任一段会让相邻段缓存失效、时长微变。因此**不能只替换单个音频**，受影响段要重跑主摄。
- 先把选择器与断言在**不录像的轻量验证器**（纯 DOM 跑通全流程）上收敛到位，再开正式录制。数据库侧的数据与渲染耗时无关，录制读的是实时应用，无需也无法复用旧数据。

## 文案与画面硬规则

| 规则 | 要点 |
|---|---|
| 禁止项 | 制作指令自述、技术术语（后端/接口/幂等/口径/字段校验/落库）、工程师抽象、臆断未验证属性、与画面不符的可见性描述 |
| 观众判据 | 任何一行文案若需要解释一个技术名词才算得通，就是不合格 |
| 控件可见性 | 描述"按钮会不会消失"前必须回源码确认是**权限门控**（状态变化仍在画面里，点了才被拒）还是**状态门控**（确实消失）；两类混用是图文不符头号来源且肉眼易漏 |
| 运行时断言 | 旁白念出的每个数字、名称、选项，录制时必须复核，不符即抛错中断；断言消息用中文写清"期望什么、实际什么、在哪一段"；断言口径与文案口径对齐 |
| 条数断言 | 按人/按记录维度的列表条数必须带容差（实测 ±1~2），且这类条数**不得写进旁白**；固定配置表才可严格相等 |
| 字典类字段 | 旁白念选项时画面必须：点开下拉 → 停留到念完 → 回读展开文本并断言与探测一致。只念不展开=看不清，展开不回读=断言形同虚设 |
| 字幕与旁白 | 字幕是短语（≤12 字，一动作一条），旁白是完整口语句，两者**不同文本** |
| 段内时序 | 切页、关弹框等改变画面的动作放在 `hold()` **之前**；补旁白宁多勿少，新增信息放段尾句 |
| 字段枚举听感 | 字段超 5 个只念 3~5 个重要字段；字段名之间必须用顿号/停顿标点分隔；听感要在测长阶段**用耳朵抽听**验证——测长只管秒数，无停顿连念在秒数上看不出任何异常 |
| 卡片停留 | 分段引导卡 **4 秒**、全片开头总览卡 **6 秒**（含淡入淡出，须为约 0.6s 的淡出压暗留余量）；卡片只插在**大阶段边界**（密度上限见 §0.5，禁止逐段插卡）；卡片正文一律按"一眼读完"设计，长文字由观众暂停查看，不上调停留时长；卡片与实录拼接前双方帧率/SAR/采样率必须归一，否则 concat 后音画错位 |
| 导航必须真实点击 | 阶段导航必须真实点击左侧菜单（逐级展开 → 点目标项），点击前先 `scrollIntoViewIfNeeded()` 把目标项滚入可视区；**用 `goto` 直达路由判不合格**——观众仍看不到导航路径 |

## 验收与交付

- 硬性门槛表与取数命令：[verification.md](verification.md)
- 一键体检：`scripts/verify-film.mjs`；逐段抽帧拼联络表：`scripts/contact-sheet.mjs`（不要逐张打开看，会漏检）；两者共用 `scripts/timeline.mjs` 读取时间轴
- **口径边界**：逐段门槛只能对**与 timeline 同源的画面轴**（未插卡的全链主摄）跑；插卡成片只跑全片级门槛。拿流程轴 timeline 去换算成片会测到静音卡片，报出一片假故障。
- **插卡密度核对**：中间卡片数量与位置按 §0.5 核对（逐张卡片抽帧 + 与 `segment-plan.md` 对清单），多一张即不合格。
- 数据可复现与等价播种：[data-reproducibility.md](data-reproducibility.md)
- 故障速查：[pitfalls.md](pitfalls.md)

交付说明必含七要素：**做了什么、为什么这样做、如何验证、剩余风险、潜在技术债、规则文档同步情况、简要复盘**。
其中"如何验证"必须给**实测数字**（成片时长、语音覆盖率、留白段数、断言条数、抽帧张数、卡片张数），不接受"看起来没问题"。

## 跨 Agent 分发

本技能按 [Agent Skills 开放规范](https://agentskills.io/specification) 编写（`SKILL.md` + `scripts/` + 参考文档），各 agent 只需把它放进自己的约定目录即可发现：

```bash
# 在项目根目录执行；先看计划再加 --apply 真正写入
node skills/rs-rec-video/scripts/link-agents.mjs --agent claude-code,cursor,codex --scope project
```

各 agent 的项目级 / 用户级目录路径、加载差异与核实来源见 [agent-compat.md](agent-compat.md)。

> **本仓库内的唯一源**：`agent-compat.md` 与 `scripts/link-agents.mjs` 以本技能这份为源，其余 `rs-*` 技能里的同名文件由仓库根 `scripts/sync-agent-compat.mjs` 生成（把文中的技能名替换为各自名字）。改这两份文件后必须跑一次 `node scripts/sync-agent-compat.mjs --apply`，提交前用 `--check` 把关。

## 项目落地文件

在目标项目根目录或 `docs/` 维护一份 `rs-rec-video-landing-<项目简称>.md`，记录：业务流程文档与片段计划位置及确认日期、工具链位置、入口约束、配音引擎与本环境重标定值、凭据通道（只记位置，绝不记明文）、已交付链路、需求方裁决与已知缺陷（带日期）。
项目已有专项文档（如 `PROJECT.md` 的视频章节）承担这些内容时**直接沿用它**，不另建重复文档。
把本技能复制到新项目时**不携带**旧项目的落地文件；换机器或重建时也不得照抄其路径，应按本文重建后回头更新它。

> **沉淀判据**：新经验先问"这条换个项目还成立吗？"——成立才进本文或对应参考文件；不成立则进该项目的落地文件。
