# 演示数据可复现（起点复位 · 逐段播种 · 等价校验）

> 适用判据：片子只有 1~2 段、跑一次就交付时，普通"录前清一遍、录后再清一遍"足够。
> **段数多（几十段）且需要反复重录局部段时**，必须升级到本文的逐段可复现起点，否则每次重录都要先跑一遍前序所有段。

## 1. 两种清理策略（按业务形态选）

| 业务形态 | 策略 | 要点 |
|---|---|---|
| 有状态机、提交后锁定（审批、日结、封账类） | **逐级回退 → 撤回 → 删明细 → 删主行** | 回退次序照抄已验收的业务回退逻辑，不要在编排里重写一份；注意存在"会把状态顶回去"的字段，回退前必须先清零；有些还原只能走 UI（SQL 直接删行不会把归档状态改回可改态），须实测确认通道 |
| 纯新增记录（基础数据、档案类） | **录制时落盘 create 返回的主键，录后按主键精确删除** | 只删自己创建的；开录前删除上一轮的主键清单文件 |

三条通用约束：

1. **起点复位与录后还原共用同一通道**——目标状态定义相同，写两份等于把踩过的坑再踩一遍。
2. **删除后必须回页面二次确认**——守卫式删除在"缺凭据/缺客户端/守卫条件不满足"时常常只打印一行提示就返回，不报错。二次确认取不到行才算真删除，取到了要抛错中止。
3. **凭据只走环境变量**——严禁出现在代码、文档、日志与提交信息里；从配置文件解析口令时，任何调试输出必须做掩码。

## 2. 逐段可复现起点（审计反推法）

目标：给定段 id，能把库**精确拨到该段开始之前**的状态，并**证明**拨对了。

### 2.1 建立审计通道（一次性，只能在捕获跑之前）

对演示涉及的业务表批量挂行级 `AFTER` 触发器，把每次写入记进一张审计表：`(表名, 主键, act ∈ {I,U,D}, seq, 改前整行 jsonb, 改后整行 jsonb)`。
配套一张 marker 表记录每段的 `(段 id, 时间戳, 序号)`，用于把写入流水切段。

- 提供 `set_triggers(bool)`：播种与还原期间**必须关触发器**，否则还原动作本身又被记进审计流水，污染后续反推。
- 重建审计表的脚本会 `DROP` 并重建流水表，**只能在捕获跑之前执行一次**；在播种阶段重跑它会摧毁本次捕获的审计流水，导致全部前缀脚本失效。
- 还原后需调用序列值修正函数（`setval` 到当前 max(id)），否则重播时主键与既有行冲突。

### 2.2 捕获跑：产出每段的 groundtruth

开着触发器把全链完整跑一遍（**不带旁白、纯动作**即可，见 2.5），得到：每段结束时刻的库指纹 + 完整审计流水。
指纹 = 逐表 `(表名, 行数, 全表校验和)`；校验和要把时间戳等易变列排除，否则等价校验永远对不上。

### 2.3 生成每段的前缀播种脚本

对段 S：取"截至 S 开始时刻"的全部审计事件，重放（或按 marker 时间戳过滤），生成把库拨到 S 起点的 `prefix-<S>.sql`。
播种脚本一律先 `set_triggers(false)`，跑完再校验。

### 2.4 基线还原：从审计流水反推，不要按前缀猜

还原到"干净基线"时必须删掉本轮新建的行、并把被改过的既有行归位。**按"演示"命名前缀删是错的**：

> 实测教训：批量保存类操作（如一次提交写几十行配置）产生的行**没有业务前缀**，按前缀删不掉，下一轮播种时又插一遍，等价校验直接表现为"行数翻倍"，且很难归因。

正确做法是从审计流水反推：

```
① 删除所有 act='I' 的行        —— 本轮新建的（含后来又被改过的），按 seq 倒序删以规避外键
② 对「有 U/D 但从无 I」的基线行 —— 取最早一条的改前整行镜像，先删后插归位
```

改前整行是 jsonb，直接反序列化成记录再插入，避免逐列拼写：

```sql
INSERT INTO tbl SELECT (jsonb_populate_record(NULL::tbl, $j$…改前整行…$j$::jsonb)).*;
```

### 2.5 等价校验与全段巡检

- 单段校验器：播种后算指纹，与该段 groundtruth 比对，逐表打印"真值 rows/ck vs 播种 rows/ck"。
- 全量巡检：按段顺序把每段都播种+校验一遍，输出失败段清单。**这是"推广到全部段"的前置门槛**——不先证明 51 段都能各自回到正确起点，就去做录制，等于把数据问题留到最贵的阶段暴露。

## 3. 还原结果核查（收尾必做）

段级等价校验只覆盖该段 groundtruth 涉及的表，**不能证明全库干净**。收尾要另做一次全库级核查：

- 逐条核对文档里点名的"必须复位项"（例如一次性初始化后 UI 无重置入口的配置表，只能 SQL 删）。
- 残留扫描**不要写死表名列名**——历史库里同类表命名往往不统一，写死会静默漏扫。遍历元数据目录里该业务前缀全部表的文本列做前缀匹配，只输出命中项；对可能缺少软删标记列的表要先探测再拼条件，否则整段扫描中途报错。
- 审计触发器在交付后应为 disabled；是否保留审计流水，取决于将来是否还要复跑等价校验，取舍要写进交付说明。

## 4. 客户端执行注意

- 执行还原/播种脚本必须开**出错即停**（如 `ON_ERROR_STOP=1`）：脚本整体包在 `BEGIN;…COMMIT;` 里时，若中途某条语句报错而进程退出码仍为 0，会表现为"脚本报成功但数据被整体回滚"，等价校验随之出现无法解释的残差。
- 中文写入与查询要显式声明客户端编码；把结果落文件再读，比直接在终端读更可靠。
